## Шаг 1. Главная: ссылка «Наши новости» и кэш

Заголовок блока «Наши новости» на главной ведёт на `/кейсы/`. Этот адрес перенаправляет сам на себя, браузер
показывает ошибку. В блоке выводятся новости, поэтому ссылка должна вести на `/news/`.

Сам блок скрыт на всех устройствах (контейнер `e69cb10`, «Расширенные → Адаптивность»), поэтому в редакторе он
бледный. Но ссылка есть в HTML-коде страницы, и роботы по ней ходят.

1. **Страницы → Главная** → «Редактировать в Elementor».
2. Вверху слева нажмите значок «Структура» (стопка листов) → найдите бледный контейнер с «Наши новости» →
   раскройте его стрелкой → нажмите на виджет заголовка. Если кликнуть по контейнеру, откроются настройки
   контейнера, в них ссылки нет.
3. Слева, вкладка «Контент», поле «Ссылка»: замените `/кейсы/` на `/news/`. Скрытие блока не трогайте.
4. «Опубликовать» (кнопка вверху справа).
5. **Elementor → Инструменты → вкладка «Общие» → «Очистить файлы и данные»** (в старых версиях — «Пересоздать CSS и данные»).
   Это уберёт и старые ссылки, которые я заменил вчера, но которые главная всё ещё показывает из кэша Elementor.
6. В верхней чёрной панели: **Performance → Purge All Caches** (W3 Total Cache), затем **Autoptimize → «Удалить кэш»**, если пункт есть.

Проверка: напишите «проверь главную».

## Шаг 2. Перенаправления (301)

Плагина перенаправлений на сайте нет, поэтому старые адреса сейчас либо отдают 404, либо WordPress «угадывает»
адрес и уводит на случайную страницу. Например, `/product-category/sla-3d-printery/` ведёт в новость про SLA-600,
а `/product-category/3d-skanery/` — в запись вебинара.

### 2а. Установить Redirection

1. **Плагины → Добавить новый** → в поиске `Redirection` (автор John Godley) → «Установить» → «Активировать».
2. Откройте **Инструменты → Redirection**, запустится мастер настройки.
3. Отметьте «Отслеживать изменения постоянных ссылок» и «Вести журнал перенаправлений и ошибок 404».
   «Хранить IP-адреса» не включайте: это персональные данные.
4. «Продолжить» → мастер проверит REST API → «Завершить настройку».

Названия кнопок в русском переводе могут немного отличаться.

### 2б. Вернуть «Комплексным решениям» адрес без «-2»

Делайте это **после** 2а: плагин сам создаст перенаправление со старого адреса.

1. **Страницы** → найдите «Комплексные решения для промышленности» с адресом `…-dlja-promyshlennosti-2` (ID 4199).
2. Наведите курсор → «Свойства» (быстрое редактирование).
3. Поле «Ярлык»: `kompleksnye-reshenija-dlja-promyshlennosti-2` → `kompleksnye-reshenija-dlja-promyshlennosti` → «Обновить».
4. В **Инструменты → Redirection** должна появиться строка `…-promyshlennosti-2/ → …-promyshlennosti/`.
   Если её нет, добавьте вручную: «Добавить новое», исходный URL `/kompleksnye-reshenija-dlja-promyshlennosti-2/`,
   целевой `/kompleksnye-reshenija-dlja-promyshlennosti/`.

Если после сохранения ярлык снова получил «-2», не продолжайте и пришлите скриншот: значит, адрес занят другой записью.

## Шаг 4. robots.txt

robots.txt на сайте — обычный файл (834 строки), WordPress его не генерирует.

1. **Yoast SEO → Инструменты → «Редактор файлов»**. Если Yoast пишет, что файл недоступен для записи, откройте
   `robots.txt` в корне сайта через файловый менеджер хостинга.
2. Сначала скопируйте всё содержимое в текстовый файл на компьютер — это резервная копия.
3. После строки `Allow: /wp-admin/admin-ajax.php` вставьте:

   ```
   Clean-param: utm_source&utm_medium&utm_campaign&utm_content&utm_term&yclid&ysclid&gclid&_openstat
   ```

4. Сохраните. Проверка: Яндекс Вебмастер → Инструменты → «Анализ robots.txt», ошибок быть не должно.

**Bing (задача 35).** В robots.txt запрещены три робота Bing: `msnbot`, `msnbot/1.0` и `msnbot-media` (картинки).
Bing исторически выполняет правила, написанные для msnbot, поэтому сайт для него фактически закрыт. ИИ-поиск
(GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot) не запрещён. Чтобы открыть Bing:

1. В том же редакторе удалите три блока (по две строки и пустая строка):

   ```
   User-Agent: msnbot
   Disallow: /

   User-Agent: msnbot/1.0
   Disallow: /

   User-Agent: msnbot-media
   Disallow: /
   ```

   Первые два — в начале списка, сразу перед блоком `ia_archiver`, третий — ниже, около строки 610 (ищите Ctrl+F `msnbot`).
2. Зарегистрируйте сайт в Bing Webmaster Tools (bing.com/webmasters): проще всего «Импорт из Google Search Console»,
   либо код подтверждения в Yoast SEO → Настройки → «Проверка веб-мастера» → Bing.
3. Там же добавьте карту сайта `https://am-tech.ru/sitemap_index.xml`.

Прямого трафика из Bing в России немного (за 4 недели в Метрике 1 визит). Смысл — видимость в ИИ-поиске Copilot и
ChatGPT, которые опираются на индекс Bing. Риск — только небольшая нагрузка от ещё одного робота.

## Шаг 5. Yoast: архивы атрибутов и типов записей

В sitemap лишние адреса двух видов.

**Три таксономии атрибутов:** «Диаметр лазерного пятна», «Размер области построения, мм», «Страна производства».
Это пустые страницы вида `/oblasti-postroenija-mm/1000-x-1000-x-600/`.

1. **Yoast SEO → Настройки** → слева раздел «Таксономии» (или «Категории и метки»).
2. Для каждой из трёх выключите «Показывать … в результатах поиска».

Архивы атрибутов в WooCommerce не отключайте: на них опирается фильтр каталога (Premmerce).

**Архивы трёх типов записей:** `/shop/`, `/cases/`, `/video-reviews/`. Они уже перенаправляются, но стояли в sitemap.
Переключатель «Архив Товары» в Yoast требует страницу магазина WooCommerce. Назначать ею «Каталог» нельзя: WooCommerce
заменит шаблон `page-katalog.php` своим списком товаров. Поэтому архивы убраны из sitemap сниппетом
**WPCode → «PHP-сниппет»** «Архивы без sitemap (SEO-агент)», «Запускать везде», «Активен»:

```php
add_filter('wpseo_sitemap_post_type_archive_link', function ($link, $post_type) {
    return in_array($post_type, ['product', 'cases', 'video_reviews'], true) ? false : $link;
}, 10, 2);
```

Сделано 14.10: страницы атрибутов отдают `noindex, follow`, в `sitemap_index.xml` 6 карт без `pa_…`, все 259 адресов
sitemap отвечают 200 без перенаправлений.

Проверка: «проверь sitemap». В `sitemap_index.xml` не должно остаться `pa_…-sitemap.xml`, а в списках товаров, кейсов
и видео — адресов `/shop/`, `/cases/`, `/video-reviews/`.

## Шаг 7. Разметка Product (задача 14) — сделано 14.10

Шаблон карточки в теме свой, поэтому WooCommerce не выводит разметку Product. Штатный вызов WooCommerce
(`generate_product_data`) на этом сайте разметку не дал, поэтому сниппет выводит JSON-LD сам.

**WPCode → Добавить сниппет → «Добавить свой код» → тип «PHP-сниппет»**, название
«Разметка Product для карточек (SEO-агент)», вставка «Автоматически», «Запускать везде», переключатель «Активен» → «Сохранить».

```php
add_action('wp_footer', function () {
    if (!function_exists('is_product') || !is_product()) {
        return;
    }
    $product = wc_get_product(get_queried_object_id());
    if (!$product) {
        return;
    }
    $text = $product->get_short_description() ?: $product->get_description();
    $text = trim(preg_replace('/\s+/u', ' ', wp_strip_all_tags($text)));
    $data = array_filter([
        '@context'    => 'https://schema.org',
        '@type'       => 'Product',
        '@id'         => get_permalink($product->get_id()) . '#product',
        'name'        => wp_strip_all_tags($product->get_name()),
        'url'         => get_permalink($product->get_id()),
        'image'       => wp_get_attachment_url($product->get_image_id()),
        'description' => mb_substr($text, 0, 500),
    ]);
    echo '<script type="application/ld+json">' . wp_json_encode($data, JSON_UNESCAPED_UNICODE) . '</script>';
}, 20);
```

В разметке только данные карточки: название, адрес, главное фото, описание. Цен и артикулов на сайте нет, бренд не
указан — часть товаров других производителей. Проверено 14.10: Product на 69 из 69 опубликованных карточек.

## Шаг 8. Видеообзоры: второй H1 (задача 18) — сделано 14.10 (вариант А)

На 44 страницах видеообзоров два H1: `<h1 class="vp-page-title">` над видео и `<h1 class="vp-title">` под ним.
Второй уже скрыт стилем темы (`.vp-title { display: none; }`), поэтому посетители его не видят, а роботы видят.
Его замена ничего не меняет внешне.

**Вариант А — сниппет WPCode (рекомендую, файлы темы не трогаем).** WPCode → «PHP-сниппет»,
название «Видеообзоры: один H1 (SEO-агент)», «Запускать везде», «Активен»:

```php
add_action('template_redirect', function () {
    if (!is_singular('video_reviews')) {
        return;
    }
    ob_start(function ($html) {
        $open = '<h1 class="vp-title">';
        $start = strpos($html, $open);
        $end = $start === false ? false : strpos($html, '</h1>', $start);
        if ($end === false) {
            return $html;
        }
        $html = substr_replace($html, '</div>', $end, 5);
        return substr_replace($html, '<div class="vp-title">', $start, strlen($open));
    });
});
```

Код меняет только этот один тег на страницах видеообзоров. Если что-то пойдёт не так, сниппет выключается одним
переключателем.

**Вариант Б — правка файла темы.** Это постоянное исправление, но риски у него такие:
- опечатка в PHP ломает страницы этого шаблона (WordPress обычно откатывает правку с фатальной ошибкой, но не всегда);
- если разработчик потом загрузит свою копию темы, правка пропадёт;
- отменить можно только из резервной копии файла.

Как делать: **Внешний вид → Редактор файлов темы** → `davlatos_theme` → файл с `video` в названии
(например, `single-video_reviews.php`) → сначала скопируйте его целиком к себе → Ctrl+F `vp-title` → в строке
`<h1 class="vp-title">…</h1>` замените `h1` на `div` в открывающем и закрывающем теге → «Обновить файл».

**По желанию — 4 ссылки в шаблонах.** После шага 2 они работают через 301, но лучше вести сразу на конечный адрес.
Найдены обходом сайта 14.10; в текстах страниц ссылок на старые адреса нет.
